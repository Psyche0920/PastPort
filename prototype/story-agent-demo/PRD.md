# Murat Story Demo：交互与呈现执行PRD

版本：1.0。状态：需求已确认，实现待返工。依据截至用户最后一次中文UI反馈；英文背景音不属于需求。

## 1. 目标与固定输入

把现有故事做成能在动画博物馆中游玩的游戏。默认第一视角环视；靠物件触发介绍、人物出场、走近和任务，使剧情发生在画面里。

- 场景：用户指定的18819动画馆，II. Murat版本，两个360°视点、14个对象。确切版本和稳定身份以本目录上一级input-lock.json为准。
- 内容：第四版《Murat的一捆柴》，六章任务、工料分流和遮护拼板、三个个人结局。历史大事件固定，选择影响个人命运。
- 最低视觉与互动参照：正式仓库demo-muradiye-ui-trial分支的adventure界面、人物步行、NPC交谈及互动效果。复用其视觉呈现与操作经验，不能只复用走动算法。
- 本任务负责人：Story Agent。3D补全由风格转绘Agent另外负责，不作为本Demo开工条件。

## 2. 核心交互

| 动作 | 必须出现的结果 |
|---|---|
| 单击物件 | 弹出该物件介绍、历史图或原文截图、出处与必要限制；人物不出场，不领取或完成任务 |
| 双击同一物件 | 取消待触发的单击，关闭介绍，转入该物件的固定分镜 |
| 分镜转场结束 | 背景停止转动，主人公从画面下方出场，成为第三视角可见角色，并自动走近物件 |
| 人物到达有效交互位置 | 自动打开该物件当前可执行的关联任务；不要求再点一次交谈按钮 |
| 固定画面中按WASD或方向键 | 在可行走地面内移动；玩家输入可中断自动走近 |
| 关闭任务 | 保留人物位置、分镜和任务进度，允许继续走动与交互 |
| 按Esc返回环视 | 停止人物移动，收起角色，恢复进入分镜前的视点与镜头；未完成任务保留 |

取消“环视／进入互动区”来回切换按钮。不得单击先弹模态框、从而让第二次点击无法命中物件。

鼠标手势由同一个识别器处理：初始双击窗口350毫秒，作为可配置交互参数；同一物件在窗口内第二次点击取消单击计时并执行走近。不同物件不拼成双击。拖动环视不触发单击。键盘Enter查看介绍，Shift+Enter走近；触摸提供对应单击／双击与屏幕方向操作。

## 3. 物件分镜和人物走近

### 3.1 UI生成前的空间检查门

这是用户确认的前置条件，执行顺序为：情节与任务规划 → 实际图片与分镜空间扫描 → 可通行范围和路径验证 → UI生成与发布候选。不能先生成可走动UI，再让玩家试出哪些地方不能走。

每个固定分镜须根据同一版本的场景图片标出可站立地面、墙体、窗户、玻璃、栏杆、楼层边缘、悬空区及遮挡，保存不可通行区域和接近点，并验证人物出场、自动接近和手动走动的完整路径。禁止仅按物件类别或统一屏幕矩形猜测通行范围。窗户表面不可穿越；窗前是否有可达地面须由图像检查决定。

空间记录必须绑定来源图像哈希、视点、镜头参数及分镜画幅；任一变化都使旧检查失效。区域未检查、结果不确定或路径碰到障碍时，禁止生成该项走动交互，保留资料查看并回到任务／分镜规划修正。UI加载时再次校验这份空间记录，不能跳过前置门。

### 3.2 分镜与角色表现

每个可接近物件单独配置：来源对象与视点、镜头yaw/pitch/FOV、有效画幅、入场点、可行走地面、障碍、接近点、交互区域、关联任务及可用条件。到达按物件附近的一片可行走区域判定，不按单个坐标点；实际区域须结合代理物位置误差逐项检查。

分镜以该物件为构图中心，同时留出人物前景和可走地面；禁止所有物件都跳到同一个入口。镜头先转场并固定，随后才显示人物。角色先由画面外进入合法落脚点，再沿有效路径走近；不能突然出现在物件旁，也不能穿墙、越栏、漂浮或穿过前景物件。

固定分镜中的角色需要待机、步行、转向和停止表现；远近缩放、脚下落点、遮挡关系保持一致。人物走动时背景不跟转。改变窗口大小后按同一分镜画幅重新投影，不能让角色与物件错位。

WASD中断自动路线后，取消本次到达触发。再次走进目标交互范围时可触发尚未打开的有效任务；离开再进入不得重复领取奖励或重复提交。同一时刻只保留一个目标与一个任务弹窗。

资料不足、没有可信落脚点或无法到达的对象，保留单击查看；双击明确提示暂不可接近，不伪造路线。14项都须列出可接近／仅查看的实际结果及原因。

## 4. 任务与人物互动

### 人物演出与自动化交接补充

每个场景的人物使用中央可站立区域内的固定站位。初始朝向玩家到达位置，此后位置和朝向不随镜头改变。多人在场时分别占位；换一句台词不替换或重新生成人物。剧本写明何时、为何进入和离开，前端按有效路线呈现自然进场、站定、交谈和离场，不能直接闪现或消失。

后续自动化分为Story Agent和前端呈现Agent两步。写作提示要求逐场、逐段提供在场名单、进出场条件与原因、站位/初始朝向、动作、台词顺序及任务/弹窗触发；前端呈现Agent再结合真实场景和素材能力落实坐标、路线、动作与窗口时序。信息不足时报告缺口，不自行补改情节。正式字段和版本待约定，当前尚未接入这套Agent自动化。当前NPC素材只有站姿，完整自然步行出入场仍缺动作素材及实机验收。

到达只触发任务界面，不代表任务完成。任务是否可用读取已有剧情进度和条件。存在多个关联任务时，按剧情顺序选当前阶段；未解锁则给出与角色处境相符的简短提示，不泄露后续答案。

NPC须以人物形象进入场景，拥有位置、朝向、待机及交谈反馈。主角面对交谈者，对白标明说话人；人物之间的互动由相应角色、镜头和对白共同表达，不能只用悬浮交谈卡代替。表现至少达到UI trial的实物参照效果。

对话、选择与小游戏在当前页面展开。弹窗期间暂停行走和输入，不在后台继续走路或刷任务；关闭后恢复原位置。小游戏只返回局部结果，由共享引擎处理剧情状态、资源、协作与结局。保留承认错误、Davud信任、母亲参与、隐私与返工的后续影响。

## 5. UI与文案

场景是主要画面，剧情使用轻量引导、人物对白和任务弹层。避免常驻的大段设计说明占据游戏画面。物件介绍、交谈、任务与操作反馈应可区分，视觉和动效与UI trial对照制作。

人名保留Yusuf、Hasan、Davud、Meryem、İlyas、Kemal、Salih等原拼写；本项目地点简称Murat。中文短、直白、易懂，角色不说开发术语。技术字段、运行状态和验收说明放在开发文档。

史料原图、出处和不确定性仍可查看；普通浏览与正式任务观察分开。动画图不能替代铭文原件，虚构账目与证词不伪装成史料。

必需观察必须按“走到该物件附近 → 打开并阅读资料 → 玩家确认读完”完成。只从资料册或远处提前打开不计入当前任务；到达后打开资料也不能自动完成，必须由玩家确认。非必需资料仍可随时浏览，不阻断主线。

### 剧情第三步：语言与说话人检查

用户于2026年10月26日明确要求，交付前逐句检查：

- 台词紧凑、简短；删除重复解释、空话和不推动情节的句子。
- 对话头像对应的人说自己的经历时用“我”，不以“他／她”指代自己。
- 提到其他人时，首次出现、隔段重提或可能混淆时，明确姓名与关系；不要让玩家回忆模糊指代。
- 旁白、人物台词、史料限制和操作提示分开呈现，不能把作者的分析直接交给人物念。
- 玩家需要的亲属关系与事件先交代，再引出反应；每句只承载一个清楚的信息点。
- 人名保留原拼写；用日常话，避免拗口比喻、翻译腔和含糊的道德感叹。

### 前景窗口与小游戏布局

所有非对话类任务、较长选择和最终结局使用屏幕中央的主面板；独立小游戏完整显示主要操作区。只有短对话和简短资料保持紧凑。最终结局必须显示明确的“故事结束”标识。

同一时间只显示一个前景交互窗口。主任务或资料覆盖其他窗口时，隐藏后面的窗口，保留台词位置、选择和小游戏进度；主任务完成或关闭后，再恢复仍未结束的下层窗口。不得同时显示两个重叠的可操作窗口，也不得把隐藏当成取消或重开。

## 6. 状态、保存与实现顺序

交互状态按以下顺序组织：

`第一视角环视 → 单击仲裁／双击选目标 → 分镜转场 → 背景固定 → 主角入场 → 自动接近／手动走动 → 到达判定 → 任务打开 → 结果提交 → 原分镜继续`

介绍、任务、手动暂停和退出均应正确取消待执行的移动或点击。保存剧情版本、对象身份、视点、当前分镜、角色位置、任务状态与已提交结果；刷新不重复触发剧情、不重复奖励。旧版存档不兼容时明确提示并保留，不静默清空。

按顺序实施：①单击／双击与铭文分镜；②主角出场、路径、WASD和到达触发；③NPC与对白呈现对齐trial；④把完整任务链与两款小游戏接回；⑤逐对象核对14项和两个视点；⑥交用户试玩，再据反馈修正并整理自动化流程。

## 8. 后续通用玩法规划（不阻塞当前返工）

用户最新优先级：先跑通现有Demo，同时规划新玩法。通用插件先配齐文字解谜、单人小游戏、特效互动三类；同类玩法换配置、素材和触发条件复用，特殊需求才新增插件，宿主不为每个遗址增加专用分支。

特效互动候选：摄像头识别指定手势后，让饮水泉喷水；厨房出现有史料依据的食材和炊事动画。启动摄像头由玩家主动选择；退出即释放，提供按钮等效操作。厨房菜品和食材须先核对来源，效果不能制造新的历史证据。摄像头能力属于后续公共能力扩展，需按main PRD的版本与生命周期规则接入。本轮不把这些规划写成已实现。


## 9. Current 3D observation and standee exceptions

User-confirmed 2026-10-26: high objects and objects behind glass, floor gaps or other impassable boundaries must not force an approach. Exclude the approach task or allow explicit reading confirmation without arrival. Check accessibility before offering an approach requirement; distance alone and missing object identity do not grant completion. Reachable ground objects retain arrival plus reading confirmation.

The current 3D demo removes the world-space 2D character standee only. Dialogue portraits, narrative characters and task progression remain. Natural staged multi-character entry/exit is a future presentation requirement; do not claim the removed standee implements it.
