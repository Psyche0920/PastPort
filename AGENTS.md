# PastPort Coding Agent Rules

- Begin with git status, the affected SDK's README/code and the relevant section of [the technical PRD](docs/TECHNICAL_PRD.md). Root README is the user entry; the technical PRD is the single cross-module specification. Do not create parallel guides, planning documents or source-module READMEs. Signatures and generated schemas remain authoritative for executable behavior.
- Preserve existing changes and keep tasks bounded. Record input/implementation identities, outputs, checks, remaining limitations and next actions in ignored run artifacts. Update the affected root/SDK README or PRD when behavior changes; do not invent acceptance evidence or rewrite history to claim completion.
- Keep Python strongly typed, immutable at boundaries, object-oriented where appropriate, with Protocol/DI separation. Domain/application/ports must not import optional SDK implementations. Use descriptive English identifiers, concise docstrings and targeted operational exceptions with deterministic cleanup.
- Reuse shared execution, budgets, provenance, review authority and the single JS game engine. No direct paid bypass, implicit model fallback, unbounded retry, duplicate Python game rules or site-specific host branches. A model, Skill or source document cannot grant permissions.
- Preserve registered project/source/object/review/spatial identities and user edits. Unknown evidence/calibration stays unknown. Private preview continuation is not historical approval or public release. Never rebuild real review databases from synthetic fixtures or reset unknown usage through resume.
- Verify the affected behavior and rendered interaction. Installation, static checks, saved-response replay, fresh generation, browser success, human game-quality acceptance and publication are separate evidence layers. New Python must pass strict typing; never weaken tests to hide an implementation defect.
- Run the relevant deterministic checks, tools/check_repository.py, tools/check_handoff.py and git diff --check. Documentation checks enforce the root README and technical PRD with their requested English translations, the root team handoff, and five SDK READMEs; machine Skills, licenses/provenance and non-document test fixtures remain separate resources.
- Do not commit, push, merge, deploy or make paid calls without task authorization. Do not spawn agents by default. Use minimum sufficient context and avoid repeated status filler. Stop immediately on a user stop instruction.

- User-requested root `handoff.md` is the team ownership/input-output/change-impact handoff. Keep it linked from README and the PRD; it is the explicit exception to the no-parallel-guides rule and must not duplicate startup or architecture specifications.

- User-requested `README.md` is the default English project entry; `README_ZH.md` is the full Chinese version. `docs/TECHNICAL_PRD_EN.md` is the English translation of the Chinese technical specification. These are language views, not separate guides or product versions. Keep structure, commands, file inventory and acceptance boundaries aligned, with reciprocal language links.

- User-requested root `CHANGELOG.md` records dated changes and verification limits; it is an allowed change history, not a parallel startup or architecture guide.
